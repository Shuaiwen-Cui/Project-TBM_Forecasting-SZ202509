# 问题分析与修复

## 问题总结

从终端输出（362-849行）可以看到两个主要问题：

### 问题1：`predict()` 方法参数冲突

**错误信息**：
```
ARIMAModel.predict() got multiple values for argument 'pred_len'
LSTMModel.predict() got multiple values for argument 'pred_len'
CNN1DModel.predict() got multiple values for argument 'pred_len'
TransformerModel.predict() got multiple values for argument 'pred_len'
```

**原因分析**：
- 在 `utils.py` 的 `measure_inference_time()` 和 `measure_batch_inference_time()` 中
- 调用方式：`model_wrapper.predict(model, x_sample, pred_len=pred_len)`
- 但 `predict()` 方法的签名是：`def predict(self, X, pred_len=None)`
- 所以 `model` 被当作 `X` 传递，`x_sample` 被当作 `pred_len` 传递，然后 `pred_len=pred_len` 又传递了一次，导致冲突

**修复方案**：
- 修改 `utils.py` 中的调用方式为：`model_wrapper.predict(x_sample, pred_len=None)`
- 因为模型在训练时已经知道了 `pred_len`，不需要再次传递

**状态**：✅ 已修复

### 问题2：LSTM模型形状错误

**错误信息**：
```
mat1 and mat2 shapes cannot be multiplied (64x32 and 64x32)
```

**原因分析**：
- 错误发生在LSTM的递归预测中（当 `pred_len > 1` 时）
- LSTM的 `hidden_size=64`，`output_size=32`（n_features=32）
- 在递归预测中，使用前一个预测值作为下一个时间步的输入
- 但LSTM期望的输入维度是 `input_size`，而前一个输出的维度是 `output_size`
- 在多变量预测中，`input_size` 应该等于 `output_size`（都是n_features），但需要确保这一点

**修复方案**：
1. 在LSTM的 `__init__` 中保存 `input_size` 和 `output_size`
2. 在 `forward` 方法中添加断言，确保 `input_size == output_size`
3. 简化递归预测逻辑，直接使用前一个输出作为输入（因为维度应该相等）

**状态**：✅ 已修复

## 注意事项

1. **维度匹配**：在多变量时间序列预测中，`input_size` 必须等于 `output_size`（都是n_features）
2. **pred_len参数**：模型在训练时已经知道了 `pred_len`，所以在预测时不需要再次传递
3. **递归预测**：LSTM、1D-CNN、Transformer都使用递归预测来处理 `pred_len > 1` 的情况
